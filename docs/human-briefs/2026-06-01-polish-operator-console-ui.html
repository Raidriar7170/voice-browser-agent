Polish Operator Console UI

结论：本阶段已完成并归档 Operator Console UI polish，把原本偏调试页的本地控制台升级为更清晰、可审计、移动端可用的 operations dashboard，同时保留 local/private 和 sanitizer 边界。

本阶段改了什么

  • 保留静态 HTML/CSS/JS 架构和现有 DOM ids，只更新本地控制台的层级、样式 token、状态 chip/badge、focus state 和响应式约束。
  • 把 command/audio review 保持为主流程，Advanced Replay、task-pack rows、normalized JSON、raw trace JSON 继续作为次级可审计区域。
  • 为 outcome、privacy、sanitizer、export、preview/local/private 等状态增加显式文字和语义 class，避免把 partial/stopped/failed/blocked/preview-only 画成成功 live execution。
  • 移动端给 readiness evidence 增加受控滚动，避免 task-pack/readiness 动态内容把命令输入完全推到首屏之外。
  • 更新静态资源 cache version 到 console-v6-20260601，防止旧 CSS/JS 缓存误导检查。

剩余风险

  • UI polish 仍是静态控制台层面的改进，不代表新增 browser execution 能力或公开发布证据。
  • 移动端 readiness 现在使用受控滚动，便于首屏看到命令输入；审查时仍应确认 scroll 区域内的 task-pack/readiness 细节可读。
  • 截图验证是本地视觉 QA 证据，权威验证仍以 tests、OpenSpec strict validation 和 local evidence artifacts 为准。
