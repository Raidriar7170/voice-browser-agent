本阶段改了什么

  • 新增 .github/workflows/reliability.yml，与 front-door.yml 分开，运行 OpenSpec strict validation 和 CI-safe pytest subset。
  • 新增 voice-browser-agent/scripts/build_reliability_snapshot.py，生成 runtime/reliability-snapshot/manifest.json，只汇总 sanitized evidence 和 optional local manifests。
  • 新增测试覆盖 workflow 形状、CI dependency strategy、snapshot 内容、privacy failure、handoff wording、stale pass count、stale OpenSpec lifecycle wording，以及 reviewer 发现的 private URL/local path 扫描缺口。
  • 更新 README、public evidence、closeout checklist、interview overview，明确 CI 不能等同于 live public browsing、recorded audio、real-provider inference 或 model training。

  • uv run python scripts/build_reliability_snapshot.py -> generated ignored runtime manifest, privacy status passed。

证据边界

  • Reliability CI 使用 pip install -e "voice-browser-agent[dev]" --no-deps 和手动依赖安装，避免依赖缺失的本地 ../../../browser-use-vision sibling checkout。
  • Snapshot privacy scanner 会拦截敏感 key、raw marker、private/loopback URL、172.16.0.0/12、10.0.0.0/8、192.168.0.0/16 和本机 /Users/ 路径。
  • Generated snapshot 不是 committed raw evidence；runtime/ 仍由 voice-browser-agent/.gitignore 忽略。
  • Full browser、real audio、optional provider、live public-readonly 和完整本地 pytest 仍是 local/private validation path，除非后续 OpenSpec change 明确把它们做成 deterministic CI-safe。

剩余风险

  • CI workflow 还需要 push 后由 GitHub Actions 实际跑一次，当前本地已验证 workflow 形状和命令。
  • uv.lock 同步了本地 editable browser-use-vision 的当前版本；这是本地 full-suite 验证产生的依赖状态变化，需要 reviewer 确认是否随本阶段保留。

推荐下一步

下一步可以做 git review、stage/commit，并在 push 后观察 GitHub Actions。不要把 reliability badge 解读成公网 live browsing 或 real-provider evidence 已在 CI 中复现。
